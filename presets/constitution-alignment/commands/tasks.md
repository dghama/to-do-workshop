## Actionable implementation and verification tasks

The verification policy in the effective tasks template is authoritative and
overrides any core command or template statement that tests are optional.
Apply it and the repository Constitution. Inspect the repository and design
artifacts before naming paths or commands. Make tasks actionable and traceable
to acceptance criteria, use real repository paths, and identify dependencies.
Name documented validation commands when available; state a concrete reason
when a relevant check cannot be run.

When generating tasks, disregard later core-command or template examples that
describe tests as optional. Include verification tasks for behavior, contract,
configuration, and data changes according to the policy above; do not impose
test-first development unless the project Constitution or feature requires it.
